# CommCodeVerifier

Программа для проверки и исправления коммерческих кодов номенклатуры перед загрузкой в 1С
и для проверки признака доступности номенклатуры в интернет-магазине (ИМ).

CommCodeVerifier — новая версия программы [CommCodeChecker](https://github.com/UncleKamineko/CommCodeChecker),
перенесённая с WinForms на WPF. Правила обработки и выходные файлы совпадают с CommCodeChecker 0.9.0.

Windows, WPF, .NET 8.

## Возможности

- **Проверка одного кода**: результат с выделением изменённых символов и списком применённых правил.
- **Групповая проверка** файла выгрузки из 1С с распределением строк по файлам:
  - коды для загрузки в 1С;
  - коды для ручной проверки;
  - неизменённые коды;
  - дубликаты.
- **Проверка признака доступности в ИМ** по отдельному файлу или по результатам групповой проверки.
- **Настраиваемый набор из 12 правил** и дополнительные параметры:
  - словоформы значащих слов;
  - допустимые символы для 1С;
  - неизменяемые сочетания кириллицы;
  - серии, для которых не удаляются окончания.
- **Внешние файлы конфигурации** (списки слов, окончаний, исключений, карта замен): правятся без пересборки.
- **Работа без зависаний**: анализ идёт в фоне, его можно прервать.
- **Настройки интерфейса**: размеры шрифтов, шесть цветовых схем; размер и положение окна запоминаются.
- **Справка** (F1) и **самопроверка правил** (Ctrl+Shift+T).

## Системные требования

| | |
|---|---|
| ОС | Windows 10 или 11, x64 |
| .NET | не требуется: среда выполнения включена в exe |
| Папка программы | с правом записи (не `Program Files`): настройки, конфигурация и результаты создаются рядом с exe |

## Установка

1. На странице [Releases](https://github.com/UncleKamineko/CommCodeVerifier/releases) скачайте архив `CommCodeVerifier.v<версия>.zip`.
2. Распакуйте его в любую папку с правом записи. В архиве:
   ```
   CommCodeVerifier.exe
   Ресурсы\Help.rtf
   ```
3. Запустите `CommCodeVerifier.exe`.

Exe не подписан цифровой подписью, поэтому при первом запуске Windows может показать окно
«Windows защитила ваш компьютер». Нажмите «Подробнее», затем «Выполнить в любом случае».

## Переход с CommCodeChecker

Скопируйте в папку с `CommCodeVerifier.exe` из папки CommCodeChecker:

- папку `Файлы конфигурации`;
- файл `settings.json`.

Формат файлов конфигурации не изменился. Настройки анализа и размеры шрифтов из `settings.json`
подхватываются автоматически.

## Файлы программы

При первом запуске рядом с exe создаются:

| Файл / папка | Назначение |
|---|---|
| `Файлы конфигурации\` | списки слов, окончаний, исключений, карта замен, правила ИМ; отсутствующие файлы создаются из шаблонов |
| `settings.json` | настройки анализа: правила, пути к файлам, доп. параметры |
| `ui-settings.json` | настройки интерфейса: шрифты, цветовая схема, размер и положение окна |
| `Результаты обработки\` | результаты групповой проверки и проверки ИМ |

Файлы конфигурации:

| Файл | Используется |
|---|---|
| `Значащие слова.txt` | правило 7 |
| `Удаляемые_окончания.txt` | правило 8 (`*` — один любой символ) |
| `Артикулы_исключения.xlsx` | правило 9: листы «Начинается с», «Заканчивается на», «Содержит» |
| `Замены символов.xlsx` | правило 10: карта замены кириллицы на латиницу |
| `Слова удаления кода.txt` | правило 12: код удаляется, если значение начинается с такого слова |
| `Исключения родительного падежа.txt` | правило 12: слова в род. падеже, не означающие другое изделие |
| `Правила проверки комм. кода для ИМ.xlsx` | вкладка «Проверка для ИМ» |
| `Правила проверки артикула для ИМ.xlsx` | вкладка «Проверка для ИМ» |
| `правила обработки значений коммерческого кода.txt` | текст правил на вкладке «Настройки анализа» |

Кодировка текстовых файлов определяется автоматически: BOM, затем UTF-8, затем Windows-1251.

## Работа с программой

| Вкладка | Что делает |
|---|---|
| **Один код** | проверка одного значения: результат, выделение изменённых символов, применённые правила |
| **Групповая проверка** | обработка файла `.xlsx` со столбцами «Номенклатура.Артикул», «Номенклатура.Коммерческий код (Общие)», «Номенклатура.Группа выгрузки ИМ (Общие)» |
| **Настройки анализа** | выбор правил, доп. параметры, свои файлы конфигурации, текст правил |
| **Проверка для ИМ** | проверка признака доступности в ИМ по отдельному файлу или по папке групповой проверки |

Кнопки в правом верхнем углу: **?** открывает справку (F1), **шестерёнка** — настройки программы
(шрифты и цветовая схема). Подробное описание есть в справке программы.

## Результаты групповой проверки

Файлы сохраняются в `Результаты обработки\ДД.ММ.ГГГГ_ЧЧ.мм`:

| Файл | Содержимое |
|---|---|
| `Коды для загрузки в 1С.xlsx` | готовые коды без дубликатов |
| `Коды для ручной проверки.xlsx` | коды для ручной проверки с выделением цветом; лист «Легенда и сводка» |
| `Комм. код не был изменён.xlsx` | строки, к которым не применилось ни одно правило |
| `Дубликаты в кодах для переноса в 1С.xlsx` | одинаковый код у разных артикулов; создаётся, только если дубликаты найдены |
| `Применённые правила.txt` | сводка по правилам и категориям строк |

## Правила обработки

Номера правил даны по ТЗ. Порядок выполнения задан в `RuleCatalog.ApplyOrder`.

| № | Правило | Пример |
|---|---|---|
| 1 | Замена точки на запятую в резьбе, размерах, числах с единицами | `Резистор 1.5 кОм` → `Резистор 1,5 кОм` |
| 2 | Удаление лишних пробелов | ` SE32-16 ` → `SE32-16` |
| 3 | Удаление служебных символов | табуляция, неразрывный пробел, символы нулевой ширины |
| 4 | Замена «х» в размерах | `20х20х3` → `20x20x3` |
| 5 | Замена символов в резьбе (`М0…` — только с дробью) | `6525 8-М5-М` → `6525 8-M5-M` |
| 6 | Замена тире на минус | `BW300D1–KIT` → `BW300D1-KIT` |
| 7 | Удаление значащих слов | `V474LM70 Butterfly valve` → `V474LM70` |
| 8 | Удаление окончания (кроме серий из настроек) | `40M6L250A0150N Cylinders series 40` → `40M6L250A0150N` |
| 9 | Удаление кода по виду артикула | артикул из `Артикулы_исключения.xlsx` → пустой код |
| 10 | Замена кириллицы на латиницу (марки стали защищены) | `РС-100А` → `PC-100A` |
| 11 | Оставить в коде только артикул | `Кольцо SRF50-25267-0015 25x68` → `SRF50-25267-0015` |
| 12 | Проверка кода после значащего слова: безусловное удаление, связь с другим изделием (предлог, родительный падеж), классификация остатка | `Крышка насоса AB12` → пустой код |

## Сборка

Нужен .NET 8 SDK. Для работы с XAML в конструкторе — Visual Studio 2022.

```bash
git clone https://github.com/UncleKamineko/CommCodeVerifier.git
cd CommCodeVerifier

dotnet build CommCodeVerifier.sln -c Release
dotnet run --project src/CommCodeVerifier.Wpf
```

В конфигурации Debug снимок конфигурации из `tests/CommCodeVerifier.Core.Tests/Config`
копируется рядом с exe как `Файлы конфигурации`. Поэтому при отладке программа работает на тех же данных, что и тесты.

Публикация одним файлом с .NET внутри, как в релизе:

```bash
dotnet publish src/CommCodeVerifier.Wpf/CommCodeVerifier.Wpf.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=none -o publish
```

То же самое делает профиль `src/CommCodeVerifier.Wpf/Properties/PublishProfiles/win-x64.pubxml`
(в Visual Studio: правый щелчок по проекту, затем «Опубликовать»).

## Тесты

```bash
dotnet test CommCodeVerifier.sln
```

| Набор | Что проверяет |
|---|---|
| `SelfTestCases` | кейсы самопроверки из `Core/SelfTest.cs`: правила 1–11, правило 12, серии без удаления окончаний |
| `BatchInvariantTests` | групповую обработку на сгенерированном файле: распределение строк, дубликаты, отмена |
| `GoldenTests` | сравнение с выходными файлами CommCodeChecker 0.9.0; без данных в `Golden/` пропускается |

Тесты используют снимок конфигурации `tests/CommCodeVerifier.Core.Tests/Config` и культуру `ru-RU`.
Поэтому они не зависят от рабочих файлов и от региональных настроек компьютера.

## Выпуск версии

В GitHub Actions два сценария:

| Файл | Когда | Что делает |
|---|---|---|
| `.github/workflows/build.yml` | каждый push и pull request | сборка и тесты на `windows-latest` |
| `.github/workflows/release.yml` | публикация релиза | тесты, публикация одним exe, прикрепление `CommCodeVerifier.v<версия>.zip` к релизу |

Как выпустить версию:
1. Releases → Draft a new release.
2. Создайте тег `v1.0.0`; для предварительной версии — `v1.0.0-alpha.1` с флажком «Set as a pre-release».
3. Нажмите Publish.

Номер версии exe берётся из тега.

## Для разработчика

- **Новая цветовая схема**:
  1. Скопируйте блок `<ResourceDictionary x:Key="…">` в `Themes/ColorSchemes.xaml`.
  2. Задайте новый ключ, название и цвета.
  3. Добавьте ключ в `Schemes.Order`.

  Схема может переопределить любую кисть `Brush.*`.
- **Размеры шрифтов** задаются ресурсами `Font.*` (`Themes/Fonts.xaml`, `Themes/FontResources.cs`)
  и применяются через `DynamicResource`.
- **Логика правил** находится только в `CommCodeVerifier.Core`. Любое изменение правил сопровождается кейсом в `SelfTest.cs`.
- Комментарии в коде пишутся по-русски и объясняют причину, а не действие.

Значок приложения: набор Softies, Elegant Themes.
